# Shoko — 書庫

観た映画・ドラマ・アニメ・同人を記録しておくための、個人用アプリ。

記録も感想も表紙画像も、**すべて自分の端末の中**に保存される。サーバもアカウントも無い。

---

## できること

- TMDB / AniList から作品を検索して登録（表紙・あらすじ付き）
- 手入力での登録（同人誌など、公開データベースに無いもの）
- 状態の管理：これから見る / 見ている途中 / 見た / 一時中断 / 見るのをやめた
- 話数の枠を API から取り込んで、**1話ごとに記録**を残す
- 作品ごとの**総評**（書き直せる）と 5 段階評価
- R18 の表紙をぼかす伏せ字表示
- 「掘り起こし」— n 年前の同じ日に書いた記録を拾い上げる
- JSON での書き出し / 読み込み

---

## 置き方

### A. GitHub Pages（無料・リポジトリは公開になる）

1. GitHub で新しいリポジトリを作る（例：`shoko`）
2. この一式をそのまま push する（またはブラウザから全ファイルをアップロード）
3. Settings → Pages → Source を `Deploy from a branch` にし、ブランチ `main` / フォルダ `/ (root)` を選ぶ
4. 数十秒後 `https://ユーザー名.github.io/shoko/` で開ける

無料プランでは、Pages は公開リポジトリでしか使えない。

### B. Cloudflare Pages（無料・リポジトリを非公開にできる）

1. リポジトリを private のまま用意する
2. Cloudflare の Workers & Pages → Create → Pages → Connect to Git
3. 対象リポジトリを選ぶ。ビルド設定は**すべて空のまま**（ビルド不要）
4. `https://xxxx.pages.dev/` が発行される

どちらの場合も、**公開されるのはアプリの入れ物だけ**で、記録したデータは一切含まれない。

## 使いはじめ

### 1. TMDB のキーを入れる

映画・ドラマの検索に必要（アニメは AniList を使うので、キー無しでも動く）。

1. https://www.themoviedb.org/settings/api でキーを取得する
2. アプリ右上の ⚙ を開き、「TMDB API キー」に貼って保存

キーは端末の中だけに保存される。**このリポジトリのコードには一切含まれていない**ので、公開しても漏れない。

うまく繋がらないときは、⚙ の「接続を確認する」で TMDB と AniList それぞれの状態を見られる。

### 2. ホーム画面に追加する（Android 推奨）

Chrome でサイトを開き、メニュー →「アプリをインストール」または「ホーム画面に追加」。

こうするとアドレスバーの無い状態で起動し、他のアプリの**共有メニューに「書庫」が出る**ようになる。

- **文字を共有** → そのタイトルで検索した状態で立ち上がる
- **画像を共有** → 表紙として扱われる。既にある作品に付けるか、新しく登録するかを選べる

スクリーンショットを撮って共有するだけで表紙が入るので、公開データベースに無い作品はこれが一番速い。
クリップボードにコピーした画像は、表紙の欄の「スクショを貼り付け」からも入る。

※ 共有メニューへの登録は Service Worker が動いてから有効になる。インストール直後に出ないときは、一度アプリを開き直す。

## バックアップ（ここが一番大事）

データは端末の中にしか無いので、**機種変更・アプリ削除・ストレージの初期化で消える**。

⚙ →「JSON で書き出す」で全件を書き出せる。手入力した表紙画像も含まれる。書き出したファイルは Google ドライブなどに置いておくのが安全。

30 日書き出していないと、起動時に上部で知らせる。

新しい端末では ⚙ →「書庫のバックアップを読み込む」で戻せる。

## ほかのアプリから引っ越す

⚙ →「ほかのアプリから取り込む（JSON / CSV）」。

ファイルを選ぶと列の対応づけ画面が出るので、どの列がタイトルか、状態か、評価かを指定する。
名前から自動で推測した状態で開くので、たいていはそのまま取り込める。

- **SakuLog**（TMDB のデータをそのまま持っている形式）は自動で判別し、
  表紙・あらすじ・評価・総評・話数ごとのメモまで丸ごと引き継ぐ。列の指定は要らない
- **AppSheet** — 元になっている Google スプレッドシートを開き、
  ファイル → ダウンロード → カンマ区切り形式（.csv）で書き出す
- 状態は「見た」「視聴中」「watched」「completed」などの表記を自動で判別する
- 評価は 10 段階でも自動で 5 段階に換算する
- 表紙は `https://` で始まる画像 URL のときだけ引き継がれる
  （Google ドライブの共有リンクは認証が要るため表示できない）
- 同じタイトルが既にある場合は飛ばすので、何度実行しても重複しない

## 表紙を入れる

作品を登録したあとでも、詳細画面の「表紙を変える」からいつでも差し替えられる。入れ方は4通り。

1. **スクショを貼り付け** — コピーした画像をそのまま
2. **写真を選ぶ** — 端末内の画像から。実物を撮った写真でも
3. **DLsite の作品番号** — RJ番号から表紙の場所を推測する。外れることもある
4. **画像の URL** — 作品ページで画像を長押し →「画像リンクをコピー」

1 と 2 は端末の中に保存されるので、リンク切れが起きない。3 と 4 は外部の画像を参照するだけなので、相手のサイトが変われば消える。

表紙の比率はまちまちでも構わない。縦長でないものは自動で全体を表示し、背景に同じ絵をぼかして敷く。
切り抜きたい / 切りたくないを個別に決めたいときは、表紙を変える画面の「表紙の見せ方」で指定する。

表紙のない作品をまとめて片付けたいときは ⚙ の「表紙をまとめて付ける」。1件ずつ順に出てくる。

## まとめて消す

⚙ の「まとめて消す」から3通り。いずれも二度押しで実行され、4秒放置すると取り消される。

- **直前の取り込みを取り消す** — 取り込んだ分だけを丸ごと戻す。試しに読み込んで気に入らなかったとき用
- **絞り込み中のものを削除** — 棚で分類や状態を絞っているとき、その範囲だけ消す
- **すべての作品を削除** — 全部消す

消したものは戻せないので、不安なら先に JSON を書き出しておく。

## ファイル構成

```
index.html              アプリ本体（これ 1 枚で全部動く）
manifest.webmanifest    ホーム画面への追加と共有メニューの設定
sw.js                   オフラインで開くための Service Worker
icons/                  アイコン
```

ビルド不要。`index.html` をブラウザで直接開いても動く。

## データの持ち方

| 置き場所 | 中身 |
|---|---|
| IndexedDB `shoko-db` | 作品・記録・総評・話数・設定・手入力の表紙画像 |
| 外部 | 何も送信しない |

書き出した JSON にはバージョン番号が入るので、将来この形式が変わっても古いファイルを判別して読める。
